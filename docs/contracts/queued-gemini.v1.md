## Interface and boundaries

Config is trusted server configuration, never HTTP/model input. Existing Gemini config fields select enabled gate, authorization, shared SponsorBudget, max_call_micro, deadline_ms (1–10,000), currentness callback, clock, model and explicit fixture/local-http transport. Credentials, reservations, caller lifecycle hooks and candidate registration are excluded. Construction/import invokes 0 transports. Default disabled; absent local transport remains unsupported, never falls back to a provider/key.

Analyze accepts only existing `GeminiInput`: `{snapshot,evidence_id,png_base64}`. Supplied selected evidence must have known clocks, a source/rights-manifest ID, EO modality, exact PNG byte length/hash/header/dimensions and a valid current snapshot. Rights ID is a binding to a server-cleared manifest, not independent license verification. Caller remains responsible for permission clearance. Existing PNG guard verifies bounded bytes/header/hash, not full decoding or image safety. Thermal/task support is not inferred.

Owned canonical outer key order is snapshot, evidence_id, png_base64. SHA-256 of that JSON forms `job:<hash>`; every snapshot field/evidence entry and selected bytes remain identity-bearing. No caller job ID/model/deadline/callback. At most 256 admitted identities retained per instance, no automatic eviction/reset. Rejected stale/invalid/full-queue inputs retain no original deadline and cannot poison identity capacity; admitted failures remain deduplicated and preserve their original deadline.

SponsorJobs owns queue, dedupe, task validation, prepayment and issued receipt/input binding. Actual Gemini client owns request/output/transport validation and reservation consumption. Wrapper narrows only the scheduler-validated analysis value. Currentness and original deadline are checked before admission, before invocation and after asynchronous result/cache reads; stale takes priority. Cached receipts keep original ID/timestamps/provenance and never become fresh calls.

Remaining client time must be positive, never clamped to a fresh1ms. Actual transport callback runs currentness then captures one final timestamp validating both snapshot and original deadline before invoking configured transport. Original scheduler/client abort is forwarded to actual transport and remains linked beyond response headers until shared physical body settlement; abort alone still proves no settlement. A prepayment already consumed by synchronous scheduler admission is not refunded on later expiry; retries reserve no additional allowance.

Counts distinguish callback `in_flight`, `queued`, `retained` and aggregate shared-budget `physical_in_flight`. Existing server-owned `on_transport_settled` fires only after actual transport/body work releases budget. Wrapper holds callback through that settlement even if deadline resolves earlier. Abort is advisory, not upstream cancellation proof. Hung calls retain both slots; queued deadlines expire without additional prepayment. No premature release, body proxy or cancellation claim.

Shared `perform` requires an untouched transferred response body. Before reading/cancelling, `bodyUsed=true` rejects with sanitized INVALID_REPLY and holds unresolved physical capacity. EOF or a second fulfilled cancel on a previously disturbed stream cannot prove its hidden first cancellation settled. Unresolved/rejected/throwing cancellation or an externally locked body also retains capacity. There is no implicit reset or release on caller deadline, closed flags or later unobserved external settlement. Untouched bodies settle at observed EOF/bodyless or fulfilled underlying cancellation initiated by `perform`; receipts keep `upstream_cancelled='unknown'`.
